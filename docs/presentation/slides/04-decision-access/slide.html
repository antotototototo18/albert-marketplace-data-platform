Label = a BigQuery “policy tag”: only people with its key can read the column · dataset = a folder of tables · ADR-0010

ANTHONY, 2 min. Our data has four sensitive columns: street, phone, city and zip code. They all sit in one table, the shipping details. We decided to protect them by type of data, not table by table. Concretely, we put a label on each sensitive column. BigQuery calls it a policy tag. Only people who hold that label's key can read the column. And the label follows the column: if a new table gets a phone column, it is protected as soon as we label it. We had two other options. One filtered view per user: but that is one more view to maintain for every new use. Or separate datasets, which are folders of tables, by level of sensitivity: but then the same data is stored twice and must stay in sync. The label is not our only protection. Our cleaning step drops street and phone before the business tables, and a test fails if personal data ever reaches gold. Now the costs, honestly. One: when the table is rebuilt, the labels disappear, with no error. We have to run a script again each time. Two: today the labels block nobody. We tested it. The course gives every student the key to every label on the project, and we cannot remove it. The other options hit the same wall, because the same student access reads every table anyway. What would change our mind: if labels keep getting lost, separate datasets are harder to get wrong. HANDOVER: Not everything went to plan. Benjamin.
